# DOC-VOICE-001 语音点餐需求与交互规范

| 项目 | 内容 |
|---|---|
| 文档编号 | DOC-VOICE-001 |
| 版本 | v1.0 |
| 状态 | 开发基线 |
| 适用版本 | CareLoop v0.3.0 语音点餐 |
| 更新时间 | 2026-08-18 |

## 1. 目标

为老人、家属和普通顾客提供低学习成本的单轮语音点餐能力。语音只负责产生候选操作，任何订单提交前必须由用户明确确认或由工作人员确认。

首期支持老人自助大屏、平板和手机浏览器，语言目标为普通话、粤语和英文；实现上优先保证中文普通话，其余语言通过浏览器语言选择和可替换适配器接入。

## 2. 首期范围

- 浏览器 Web Speech API `SpeechRecognition`：语音转文字。
- 浏览器 `speechSynthesis`：系统提示、候选结果和确认反馈的播报。
- 单轮模式：一次录音只解析一个用户意图。
- 支持加菜、数量、口味要求、餐桌、确认、取消和请求工作人员。
- 支持模糊菜名、口语表达、数量表达和多项口味要求。
- 识别结果先进入预览，不直接创建或确认订单。
- 识别失败或连续低置信度时进入工作人员协助流程。
- 为后续连续对话预留会话、槽位和事件模型。

## 3. 非目标

- 首期不实现真正的多轮上下文对话。
- 首期不依赖云端语音服务。
- 不以语音识别结果替代支付确认。
- 不保存长期原始录音，不用于未经授权的模型训练。

## 4. 核心用户流程

```text
进入点餐页
  ↓
点击“说一说”并授权麦克风
  ↓
录音 5~10 秒，显示实时状态
  ↓
结束录音 / 浏览器返回转写文本
  ↓
规范化与意图解析
  ↓
展示文字、菜品候选、数量、口味、餐桌
  ↓
用户点击确认或重新说
  ↓
加入购物篮 / 更新草稿
  ↓
最终订单页再次确认
```

## 5. 老人友好交互要求

- 使用大按钮、大字号、高对比度，语音按钮至少 64px。
- 每次只询问一个缺失信息，例如“请选择餐桌”，不要一次播报多个问题。
- 所有语音结果同时以文字和卡片呈现，避免只依赖听觉。
- 识别中显示“正在听，请慢慢说”；识别结束显示“我听到的是……”。
- 提供“重新说”“手动选择”“请工作人员帮助”三个稳定出口。
- 对方言、吐字不清和环境噪声，不直接判定失败，先展示候选并允许手动修正。
- 口味要求使用独立标签展示，例如“少盐”“不辣”“易咀嚼”，不得隐藏在备注中。
- 关键操作使用二次确认：加入购物篮确认一次，提交订单确认一次。

## 6. 语音按钮状态

| 状态 | 用户看到的内容 | 可执行操作 |
|---|---|---|
| idle | 点击说一说 | 开始识别 |
| listening | 正在听，请慢慢说 | 停止、取消 |
| transcribing | 正在理解 | 等待 |
| needs_confirmation | 显示解析卡片 | 确认、修改、重说 |
| failed | 没听清或暂不可用 | 重试、手动选择、找工作人员 |

## 7. 成功与失败标准

成功标准：用户能看见转写文本和结构化候选，并主动确认后才修改购物篮或订单。

失败标准：无麦克风权限、浏览器不支持、超时、空文本、置信度过低、菜品无匹配、餐桌非法或意图不明确。失败时不得创建错误订单。
